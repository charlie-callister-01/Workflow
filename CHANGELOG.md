# Changelog

One line per change to the workflow, newest first: what changed and why. Bigger choices get a note in `notes/decisions/`.

## 2026-11-23
- v2 planning: resolved roadmap decision ticket 22, a fast ideas inbox: a global user-only `/idea` skill, a project inbox in `docs/IDEAS.md` created on first use, toolbox ideas as GitHub `idea` issues (decision 0007), triage by `/idea` with no text; glossary terms Idea, Inbox, Triage. Why: capture an idea in seconds mid-task, from any machine, and route it into the map.
- **v2, first change:** `AGENTS.md` is the project's instruction file and `CLAUDE.md` is the single line `@AGENTS.md`, promoted from the beta track (trial verdict: keep; decision 0006 accepted). `templates/AGENTS.md` is new, `templates/CLAUDE.md` is one line, `Install-Workflow.ps1` installs both (and skips them when a project has only `CLAUDE.md`), `/setup-workflow` fills in `AGENTS.md`, `/refit-workflow` moves `CLAUDE.md` to `AGENTS.md` with `git mv`. Beta overlay and `workflow_track: beta` removed from the production copies; `beta/` is empty. SETUP, USING, CUSTOMISING, `presets/lite.md`, README and GLOSSARY updated. Why: one instruction file for every agent; this starts v2, since v1 changes only for fixes.
- v2 planning: roadmap decision ticket 23, updating the workflow in an older project (a new `/update-workflow` skill or a mode of `/refit-workflow`); the "Distribution and updates" fog line now covers distribution only. Why: refit is built for merging two workflows, not for taking toolbox changes since `workflow_version`.
- v2 planning: roadmap decision ticket 22, a fast ideas inbox (capture a one-line idea mid-task, then sort it into the wayfinder map). Why: adding to `notes/ideas.md` is slow and nothing routes ideas into the map.
